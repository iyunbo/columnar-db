Architecture

Five layers, bottom to top. Each layer only depends on the one below it.

┌─────────────────────────────────────────────┐ │ REPL (cmd/) │ │ Interactive SQL shell │ ├─────────────────────────────────────────────┤ │ SQL Frontend (sql/) │ │ Lexer → Parser → Planner → Execute │ ├─────────────────────────────────────────────┤ │ Vectorized Execution (exec/) │ │ Scan · Filter · Project · Aggregate │ │ GroupBy · OrderBy · Limit │ ├─────────────────────────────────────────────┤ │ Encoding & Compression (encoding/) │ │ Plain · RLE · Dictionary · Delta · LZ4 │ ├─────────────────────────────────────────────┤ │ Column Storage (storage/) │ │ RowGroup · ColumnChunk · NullBitmap │ │ Writer · Reader · File Format │ └─────────────────────────────────────────────┘

Data Flow

A query moves through the system like this:

  1. REPL reads a SQL string from the user
  2. Lexer tokenizes it into a stream of tokens
  3. Parser builds an AST (SelectStmt)
  4. Planner translates the AST into an operator tree
  5. Operators pull batches of ~1024 rows through a pipeline
  6. REPL drains the pipeline and formats the output

Query Pipeline Example

SELECT city, COUNT(*), AVG(age)
FROM people WHERE age > 30
GROUP BY city ORDER BY city

  ScanOp          ← reads RowGroup, yields Batches
    ↓
  FilterOp        ← narrows selection (age > 30)
    ↓
  GroupByOp       ← hashes by city, runs aggregators
    ↓
  OrderByOp       ← sorts result by city ASC
    ↓
  results

Operator Contract

All operators implement a pull-based interface:

type Operator interface {
    Next() (*Batch, bool)   // pull next batch, false = done
    Reset()                 // rewind for reuse
}

Each Next() returns a Batch of up to 1024 rows. Operators compose — each one wraps the operator below it and transforms the stream.
