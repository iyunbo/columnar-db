columnar-db — Architecture

Static snapshot of the codebase as of Phase 4 Step 1 (main, exec package has the Operator interface + ScanOp, FilterOp, ProjectOp, Vector, Batch, Selection, Predicate; Phase 4 has added the Aggregator interface and the AggregateOp operator stub — implementation lands in Steps 2–5).

Layered View

exec (execution engine) storage (in-memory columnar types) encoding (compression & encodings) persistence (file I/O) interface / abstract type

Key Concepts

Type Role Lives in
Operator (interface) Pull-based contract: Next() (*Batch, bool) + Reset(). Every operator implements it; pipelines compose by wrapping children. exec/operator.go
ScanOp Source: walks a RowGroup in ≤1024-row batches, yields a reused *Batch with full Sel. exec/scan.go
FilterOp Narrows Batch.Sel via a Predicate. Vectors untouched; O(1) pointer swap with a scratch selection. Fully-filtered batches skipped. exec/filter.go
ProjectOp Drops/reorders columns by pointer-aliasing a subset of the child's Vectors. Sel passes through. Zero copy. exec/project.go
Predicate (interface) Eval(vec, in, out *Selection). Int64: Eq / Ne / Lt / Le / Gt / Ge. Nulls never match (three-valued logic). exec/predicate.go
Batch Aligned Vectors []*Vector + Sel *Selection. Row i is the same tuple across all columns. exec/batch.go
Vector One column's ≤1024-row batch. Wraps a typed storage.Column + NullBitmap. Int64s() / Float64s() / ... expose raw slices for hot loops. exec/vector.go
Selection Compact []uint16 of live row indices inside a batch. The late-materialization primitive: vectors never shrink, only this index list does. exec/selection.go
RowGroup Horizontal slice of a table — a bundle of ColumnChunks sharing a row count. Unit of parallel read and skip-scan. storage/rowgroup.go
ColumnChunk Named + typed column: Column values + NullBitmap + stats (min/max/null count). storage/chunk.go
Column (interface) Typed contiguous array. Concrete: Int64Column, Float64Column, StringColumn, BoolColumn. storage/types.go
NullBitmap Bit-packed null tracking — 1 bit per row, 8× smaller than []bool. Shared between ColumnChunk and Vector. storage/bitmap.go
SingleFileWriter / Reader .cldb binary format. Layout: magic CLDB → row groups → footer → footer length (4B LE) → magic. Footer-at-end, seekable, Parquet-style. storage/writer.go, reader.go, format.go
Encoder (interface) Column-aware compression: Plain, RLE, Dictionary, Delta. Writer picks per chunk; metadata records the choice. encoding/
LZ4Compressor Block compression on top of the column encoding — operates on encoded bytes. encoding/lz4.go

Data Flow

Write   typed Columns + NullBitmap → ColumnChunks → RowGroup → SingleFileWriter → per-chunk Encoder → LZ4 → bytes; footer appended on Close().

Read   SingleFileReader.Open reads footer → ReadRowGroup(i) decompresses + decodes → in-memory RowGroup.

Execute   ScanOp (reused Batch, full Sel) → FilterOp (swaps Sel with narrowed scratch) → ProjectOp (rebinds Vectors subset, shares Sel) → consumer iterates b.Sel.Indices().

Coming in Phase 3 Step 6: end-to-end pipeline benchmark (Scan → Filter → Project, zero alloc, ≥5× vs row-at-a-time).

Invariants

  • Layout — Vector.Values.Len() == length: nulls store a zero placeholder so row i is the same position in the typed slice and the bitmap.
  • Alignment — every Vector in a Batch has identical Len(). Row i is the same tuple across columns. Only Sel shrinks.
  • Zero-alloc hot path — Batch / Vector / Selection allocated once at operator construction and recycled via Reset(). Enforced by AllocsPerRun tests.
  • Late materialization — no operator rebuilds rows. Values stay column-wise from disk to the final result.
