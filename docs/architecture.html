columnar-db — Architecture

Static snapshot of the codebase as of Phase 3 Step 2 complete (main, exec package has Vector, Batch, ScanOp).

Layered View

exec (execution engine) storage (in-memory columnar types) encoding (compression & encodings) persistence (file I/O) interface / abstract type

Key Concepts

Type Role Lives in
ScanOp Source operator of the vectorized engine. Holds a *RowGroup, walks it in chunks of ≤1024 rows, and yields a reused *Batch per Next() call. Zero allocations after construction. exec/scan.go
Batch Set of aligned *Vectors — one per output column. All vectors share the same length; row i refers to the same tuple across columns. exec/batch.go
Vector A ≤1024-row batch of one column. Wraps a typed storage.Column (pre-sized to VectorSize) plus a NullBitmap. Exposes Int64s() / Float64s() / ... so filter hot paths iterate raw slices with no interface calls. exec/vector.go
RowGroup Horizontal slice of a table: a bundle of *ColumnChunks that share a row count. Real-world row groups are ~65k rows each; they are the unit of parallel read, skip-scanning, and file-level indexing. storage/rowgroup.go
ColumnChunk Named + typed column for one row group. Combines a Column (values) with a NullBitmap and stats (min/max/null count). The building block that row groups are made of and that the file format serializes. storage/chunk.go
Column (interface) Abstract contract for a typed contiguous array. Implemented by Int64Column, Float64Column, StringColumn, BoolColumn — each backed by a plain typed slice, with Append / AppendSlice / Reset methods. storage/types.go + int64.go / float64.go / string.go / bool.go
NullBitmap Bit-packed null tracking — 1 bit per row, 8× smaller than []bool. Shared between ColumnChunk (persistent) and Vector (per-batch). Reset() zeros in place for reuse. storage/bitmap.go
SingleFileWriter / SingleFileReader .cldb binary file format. Layout: magic "CLDB" → row groups → footer (schema, row-group index, column stats) → footer length (4B LE) → trailing magic "CLDB". Footer-at-end makes the file self-describing and seekable, same pattern as Parquet. storage/writer.go, storage/reader.go, storage/format.go
Encoder (interface) Column-aware compression. Plain = raw baseline, RLE = run-length for repeated values, Dictionary = index lookup for low-cardinality strings, Delta = differences for sorted integers. Writer picks an encoding per column chunk; metadata records the choice. encoding/encoder.go + plain.go / rle.go / dictionary.go / delta.go
LZ4Compressor General-purpose block compression applied on top of the column encoding. Works on the encoded byte stream, not the raw values — cheap to decode in the read path. encoding/lz4.go

Data Flow

Write path (in-memory → disk)
  1. Caller builds typed Columns (Int64Column, …) with raw values + a NullBitmap.
  2. ColumnChunks wrap them (one per column) and compute stats.
  3. RowGroup bundles aligned chunks.
  4. SingleFileWriter.WriteRowGroup → picks an Encoder per column chunk → LZ4Compressor → writes bytes.
  5. Footer (schema + row-group index + column stats) is appended at Close().
Read path (disk → in-memory → execution)
  1. SingleFileReader.Open seeks to end, reads footer offset + footer, learns layout.
  2. ReadRowGroup(i): fetch bytes for each requested column → LZ4 decompress → decode via the recorded Encoder → reconstruct Columns + NullBitmap → assemble a RowGroup.
  3. NewScanOp(rg, []string{…}) allocates one output Batch of pre-sized Vectors (one per requested column).
  4. On each Next(): Batch.Reset() → Vector.CopyFromChunk(chunk, offset, n) does one typed memmove per column per batch → returns the reused *Batch.
  5. (Coming in Phase 3 Steps 3–6) FilterOp.Next → apply predicates, produce a Selection → ProjectOp.Next → drop unused columns → consumer.

Key Design Invariants

  • Layout invariant (Vector): Values.Len() == length at all times — nulls store a zero-value placeholder in Values so row index i is the same position in both the typed slice and the null bitmap. Lets the filter hot path index the typed slice directly.
  • Alignment invariant (Batch): every Vector in a Batch has identical Len(). Row i refers to the same tuple across all columns. Operators that shrink batches do so via Selection, not by resizing vectors.
  • Zero-alloc hot path: Vector and Batch are allocated once at NewScanOp and recycled. Reset() truncates backing slices in place and zeros bitmaps. Enforced by TestScanZeroAllocPerBatch.
  • Late materialization (planned): no operator reconstructs full rows. Values live column-wise in batches from disk to the final result — aggregates may never materialize rows at all.
